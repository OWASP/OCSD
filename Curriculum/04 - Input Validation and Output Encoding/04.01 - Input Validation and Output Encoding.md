# Module 4 – Input Validation and Output Encoding

This outline defines the knowledge and skills assessed in Module 4.

## 4.1 Untrusted data

- Untrusted data sources, including form fields, URL paths and query parameters, HTTP headers, cookies, request bodies, file names, and file content
- Data from databases, internal services, message queues, and third-party APIs as untrusted input when another party can influence it
- The trust boundary between clients and the server, and the treatment of all client-supplied data as untrusted
- Injection as the interpretation of untrusted data as code, commands, or structure by an interpreter
- The distinction between validation, sanitization, normalization, and encoding, and the purpose of each
- The complementary roles of input validation, parameterized APIs, and output encoding in a layered defense
- The limits of input validation as a defense against injection and cross-site scripting

## 4.2 Input validation

- Server-side enforcement of all security-relevant validation
- Client-side validation as a usability aid that a caller can bypass
- Allowlist validation that defines accepted input and rejects everything else
- The weaknesses of blocklist validation and filter-based defenses
- Syntactic validation of type, length, range, format, and allowed values
- Semantic validation of input against business rules
- Schema validation for structured input such as JSON and XML
- Normalization and canonicalization before validation, including character encodings, Unicode representations, and encoded traversal sequences
- Rejection of invalid input with generic error messages
- Validation libraries and framework validation features instead of custom validation logic
- Denial of service through unsafe regular expressions
- Conversion of validated input into typed values and objects at the trust boundary

## 4.3 Injection prevention

- The separation of code and data as the principle behind parameterized APIs
- SQL injection and its prevention with parameterized queries and prepared statements
- Object-relational mappers and query builders, including their unsafe raw-query features
- Least-privilege database accounts as defense in depth
- NoSQL injection through query operators and unvalidated request structures
- OS command injection and its prevention by avoiding shell interpreters, using safe APIs, and passing arguments separately
- LDAP injection and the escaping of filter metacharacters
- XML external entity injection and parser configuration that disables document type definitions and external entities
- XPath injection and parameterized XPath APIs
- Template injection when untrusted data is placed into server-side templates
- Header injection through carriage return and line feed characters in header values
- Escaping specific to the target interpreter as a last resort when no parameterized API exists

## 4.4 Output encoding and cross-site scripting prevention

- Cross-site scripting as the execution of untrusted data in a user's browser
- Reflected, stored, and DOM-based cross-site scripting
- Output encoding applied at the point of output for the destination context
- HTML body, HTML attribute, JavaScript, URL, and CSS contexts, and the encoding each requires
- The failure of encoding applied for the wrong context or applied more than once
- Automatic encoding in templating engines and the features that bypass it
- Dangerous sinks in client-side code, such as APIs that insert raw HTML
- Correct content types and encoding for data placed in JSON responses
- HTML sanitization with a maintained library when rich content is a requirement
- The failure of custom filtering and regular expressions as cross-site scripting defenses
- Content Security Policy, cookie attributes, and framework protections as defense in depth rather than primary defenses

## 4.5 Testing input and output handling

- Positive tests for accepted input and negative tests for rejected input
- Boundary values, oversized input, unexpected types, and malformed structures
- Tests using known attack payloads and encoding variations
- Verification of encoding in each output context that displays untrusted data
- Tests that call endpoints directly and bypass client-side validation
- Regression tests for fixed validation, injection, and encoding defects
- The roles of static analysis, dynamic testing, and fuzzing in finding input-handling defects
