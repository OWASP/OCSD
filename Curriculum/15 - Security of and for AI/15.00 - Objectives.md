# Objectives for Module 15 – Security of and for AI

This module covers the security of applications that use large language models.
It takes the position of a developer integrating a model, and leaves the building and training of models out of scope.

A successful candidate can:

- Distinguish what an application controls in a model-backed feature from what it does not, including the model, the system prompt, retrieved content, and tool access
- Recognize that a model cannot reliably separate instructions from data
- Identify where untrusted content enters a prompt, and the forms prompt injection takes: direct, indirect, and cross-modal
- Recognize what input filtering and prompt wording achieve, and why neither establishes a trust boundary
- Identify what prompts, system instructions, and surrounding context expose, and recognize that no control may depend on keeping that content secret
- Recognize the consequences of giving a model access to data, tools, and actions, and identify the limits each one needs
- Identify supply chain and poisoning risks in models, adapters, datasets, and retrieval sources
- Identify the access controls and tenant boundaries that apply to a vector store used for retrieval
- Identify the cost, availability, and model extraction risks that follow from uncontrolled inference
- Recognize model output as untrusted input, including code produced by a coding assistant, and identify the handling each destination requires
- Distinguish fluent model output from verified information
- Identify where an application must ground, attribute, or confirm what it presents

## Expected competency

Candidates can recognize whether an application constrains what a model can read, reach, and do.
They can identify where untrusted content enters a prompt, and where model output needs the same handling as any other untrusted input.
