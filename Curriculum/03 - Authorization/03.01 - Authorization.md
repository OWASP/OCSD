# Module 3 – Authorization

This outline defines the knowledge and skills assessed in Module 3.

## 3.1 Authorization foundations

- The distinction between authentication and authorization
- The use of authenticated identity as an input to authorization decisions
- Public resources and operations that do not require an authenticated identity
- Subjects, actions, resources, policies, permissions, and contextual information in an authorization decision
- The effect of authorization decisions on the confidentiality, integrity, and availability of protected resources

## 3.2 Access-control principles and models

- Least privilege, deny by default, complete mediation, and separation of duties as authorization principles
- Explicit authorization rules for users, services, actions, resources, and relevant context
- Authorization matrices as representations of expected access
- Access control lists that assign permissions to subjects for a resource
- Role-based access control and the relationship among users, roles, and permissions
- Attribute-based access control using attributes of the subject, resource, action, and environment
- Relationship-based access control using relationships such as owner, member, parent, or delegate
- The benefits and limitations of each access-control model in a web application
- The separation of policy definition, authorization decisions, and policy enforcement

## 3.3 Authorization enforcement

- Enforcement at a trusted application layer for every protected operation
- Authorization decisions based on the current subject, action, resource, policy, and context
- Consistent checks across user interfaces, endpoints, HTTP methods, services, background operations, and data access
- The difference between hiding a user-interface control and enforcing authorization
- The treatment of unverified client-supplied identities, roles, permissions, ownership claims, and tenant identifiers as untrusted input
- Centralized or reusable authorization mechanisms that reduce missing and inconsistent checks
- Denial of access when no rule grants permission or an authorization decision cannot be completed
- The security implications of framework defaults, annotations, middleware, and other authorization features

## 3.4 Authorization scope and common failures

- Function-level authorization for application operations, including administrative functions
- Object-level authorization for specific records, files, and other resources
- Property-level authorization for reading or changing individual fields
- Tenant boundaries as part of each applicable authorization decision
- Insecure direct object references and broken object-level authorization as failures to authorize access to a requested object
- Broken property-level authorization, including unauthorized fields in requests and responses
- Horizontal privilege escalation between users with similar privileges
- Vertical privilege escalation from a lower level of privilege to a higher level
- Random or opaque resource identifiers as defense in depth alongside authorization controls

## 3.5 Authorization testing

- Test cases derived from documented authorization rules or an authorization matrix
- Positive tests for permitted actions and negative tests for denied actions
- Tests with unauthenticated users, multiple users with the same privileges, different privilege levels, and different tenants
- Tests for function-level, object-level, property-level, and cross-tenant access
- Tests that bypass the user interface and call protected operations directly
- Coverage of relevant operations, endpoints, HTTP methods, and resource states
- Automated regression tests that change with authorization requirements and application features
