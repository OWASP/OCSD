# Objectives for Module 16 - Secure Development Environment

A successful candidate can:

- Recognize why developer workstations are high-value targets, identify assets and common threats affecting development environments, and select controls that reduce the likelihood or impact of compromise.
- Select appropriate workstation-hardening controls for a stated development scenario, including least privilege, separation of development and production access, disk encryption, screen locking, endpoint protection, host firewalling, patching, secure configuration, and removal of unnecessary software.
- Recognize developer responsibilities under organizational security policies, including acceptable use, software installation, cloud and online-service usage, data handling, production access, incident reporting, and escalation of security concerns.
- Identify security risks introduced by IDEs, editors, extensions, language servers, build tools, command-line utilities, package managers, Git hooks, and other locally installed development tools, and select appropriate controls such as trusted sources, restricted permissions, workspace trust, updates, lockfiles or version pinning, and removal of unnecessary tools.
- Evaluate the security and data-handling risks of online developer services, paste sites, code assistants, formatters, converters, debuggers, and other third-party tools, and determine when proprietary, sensitive, or regulated information must not be submitted to them.
- Recognize inappropriate storage, transmission, logging, committing, or sharing of passwords, API keys, tokens, private keys, session credentials, production data, and other sensitive development or test data, and select appropriate secrets-management, secret-detection, data-minimization, sanitization, and credential-rotation practices.
- Select secure practices for corporate, home, and public network environments, including approved remote-access mechanisms, secure Wi-Fi, VPN or equivalent protected access where required, SSH credential protection, and avoidance of unauthorized tunnels or publicly exposed development services.
- Recognize risks from locally running development servers, databases, administrative interfaces, dashboards, and debugging services, and select appropriate controls for network binding, authentication, privilege, credentials, service lifetime, and external exposure.
- Explain the security benefits and limitations of containers, virtual machines, development containers, cloud workspaces, and managed development environments, and recognize unsafe configurations such as privileged execution, unnecessary host mounts, exposed container-runtime sockets, excessive privileges, untrusted images, or exposure of host credentials.
- Recognize developer-targeted social-engineering and supply-chain attack techniques involving phishing, malicious repositories, pull requests, packages, scripts, commands, extensions, links, or credential requests, and select a response that verifies the source and avoids executing or trusting unverified content.
- Select secure everyday developer practices, including locking unattended devices, using MFA, reviewing commands before execution, inspecting code changes and Git diffs before commit, separating work and personal activities, and sanitizing logs, screenshots, and diagnostic information before sharing.
- Recognize indicators of possible workstation, credential, repository, or development-account compromise and select appropriate immediate actions, including stopping potentially unsafe activity, protecting or preserving relevant information, revoking or rotating exposed credentials and sessions where appropriate, and promptly reporting through the organization’s incident-response process.
- Identify and use appropriate sources of security information, including vulnerability and security advisories, organizational guidance, vendor bulletins, and relevant OWASP resources, to maintain awareness of issues affecting the languages, frameworks, dependencies, tools, and environments used for development.
- Evaluate a supplied developer-environment scenario or security checklist, identify insecure practices, excessive exposure, or missing controls, and select practical improvements that reduce risk while preserving an effective development workflow.


## Expected Competencies

Candidates can distinguish secure from insecure developer-environment practices in ordinary software-development scenarios and select an appropriate control, response, or safer alternative.
