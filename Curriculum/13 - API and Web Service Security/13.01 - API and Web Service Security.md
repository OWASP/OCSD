# Module 13 – API and Web Service Security

This outline defines the API and web service security knowledge assessed in Module 13.

## 13.1 APIs and their risks

- APIs as interfaces used by browsers, mobile applications, other services, and third parties
- Why APIs expose object identifiers, data structures, and business functions more directly than user interfaces
- Why clients can call any API endpoint directly, regardless of the user interface
- The OWASP API Security Top 10 (2023) as a catalog of common API risks

## 13.2 Authentication and authorization for APIs

- Authentication on every request, and the transport of credentials and tokens in headers rather than URLs
- Broken authentication in APIs: endpoints without authentication, unvalidated tokens, and unprotected login and token endpoints
- API keys as identifiers of a calling application rather than of a user, and their limits as a sole authentication method
- Validation of access tokens on every request, including signature or status, issuer, expiry, audience, and scope
- Object-level authorization for every object identifier in a request, including identifiers in paths, query strings, bodies, and headers
- Function-level authorization for every endpoint and HTTP method, including administrative endpoints
- Property-level authorization for fields that a client reads or changes
- Mass assignment, in which an API binds request fields to internal objects without an allowlist
- Excessive data exposure, in which an API returns more fields than the client needs and relies on the client to filter them
- Authentication between services, including the OAuth 2.0 client credentials flow and mutual Transport Layer Security (TLS)

## 13.3 Request and response handling

- Validation of requests against a schema or API specification, including types, formats, required fields, and unexpected fields
- Checking the declared content type and rejecting unsupported formats
- Limits on request size, array length, nesting depth, and string length
- Safe parser configuration for structured formats such as JSON and XML, and risks of deserializing untrusted data
- Response content types and generic error responses, as described in Modules 4 and 6
- CORS for browser-based API clients, including preflight requests, and why CORS does not replace authentication or authorization
- Protection against cross-site request forgery for APIs that use cookie-based authentication

## 13.4 Resource consumption

- Unrestricted resource consumption as a cause of denial of service and unexpected cost
- Rate limits per client, user, and operation, and quotas over longer periods
- Limits on page size, query results, batch operations, and uploaded data
- Timeouts for requests and for calls to other services
- Costly operations that third parties bill per call, such as messages, payments, or AI model requests
- Responses for limited requests, such as status code 429 and retry information
- The distinction between resource limits and the protection of sensitive business flows against automated abuse, such as bulk purchases or mass account creation, which relates to the anti-automation controls in Module 11

## 13.5 API styles

- REST: resource-oriented endpoints, HTTP methods, and authorization per method
- GraphQL: a single endpoint, authorization in each resolver, query depth and complexity limits, batching and aliases that bypass rate limits, and introspection in production
- SOAP and other XML-based services: XML parser hardening and the validation of message signatures
- gRPC: transport protection, authentication through request metadata, message validation, and server reflection in production

## 13.6 Webhooks and outbound requests

- Webhooks as API calls that a service sends to a URL registered by another party
- Verification of received webhooks with signatures that cover the body, timestamp, and event identifier, and replay protection
- Idempotent processing of webhook events that may be delivered more than once
- Sending webhooks: signing each delivery, a separate rotatable secret per subscriber, and delivery timeouts and retry limits
- Server-side request forgery (SSRF) when an API fetches a URL supplied by a client, including webhook registrations
- SSRF controls: allowlists of destinations, blocking internal and metadata addresses, connecting to the address that was checked, revalidating redirects, and restricting outbound network access
- DNS rebinding as a way to bypass address checks that resolve a host name more than once

## 13.7 Consuming third-party APIs

- Unsafe consumption of APIs: treating data from third-party APIs as trusted
- Validation of third-party responses before use, as with other untrusted input
- Transport protection, timeouts, redirect handling, and response size limits for outbound calls
- Protection and least-privilege scoping of credentials for third-party APIs
- Effects of a compromised or unavailable third-party API on the application

## 13.8 API configuration, inventory, and lifecycle

- Security misconfiguration in APIs: unused HTTP methods, missing TLS or security headers, verbose errors, permissive CORS, default credentials, and outdated API software

- Inventories of APIs, versions, environments, and data flows
- API documentation and specifications as a basis for security review and testing
- Risks of undocumented, deprecated, and old API versions that remain reachable
- Exposure of non-production APIs and their data
- API gateways for central authentication, rate limiting, and routing, and their limits for object-level authorization

## 13.9 API security testing

- Authorization tests across users, objects, properties, endpoints, and HTTP methods
- Tests that send unexpected fields, types, sizes, and content types
- Tests that exceed rate limits, page sizes, and query complexity
- Tests for webhook signature and replay checks and for SSRF in URL-fetching features
- Use of API specifications for fuzzing and for contract tests of documented endpoints
- Discovery of undocumented endpoints through logs, traffic analysis, and scanning, which specification-based tests cannot find
