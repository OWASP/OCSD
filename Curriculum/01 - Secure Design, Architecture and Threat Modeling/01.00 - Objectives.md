# Objectives for Module 1 – Secure Design, Architecture and Threat Modeling

This module covers security decisions made during design and the use of threat modeling to turn risks into development work.

A successful candidate can:

- Explain how security activities fit into the software development lifecycle
- Identify assets, components, data flows, entry points, trust boundaries, and security assumptions in a system description
- Apply essential secure design principles to identify weaknesses in a design
- Use the Four Question Framework to contribute to threat modeling
- Use STRIDE and application context to identify and prioritize threats
- Express agreed mitigations as security requirements, implementation work, and tests
- Record and communicate assumptions, decisions, and residual risks

## Expected competency

Candidates can review a web application design and contribute to its threat model as part of a team.
They can translate agreed security decisions into development and test work.
