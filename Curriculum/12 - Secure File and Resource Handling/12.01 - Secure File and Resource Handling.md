# Module 12 – Secure File and Resource Handling

This outline defines the file and resource handling knowledge assessed in Module 12.

## 12.1 File handling risks

- Application features that handle files: uploads, downloads, generated files, imports, previews, and conversions
- Consequences of unsafe file handling: server-side code execution, cross-site scripting through served files, unauthorized file access, malware distribution, and denial of service
- File names, paths, types, sizes, and contents as untrusted input

## 12.2 Validating uploaded files

- Allowlists of permitted file types for each upload feature
- Why the client-supplied `Content-Type` header and file extension cannot be trusted
- Checks of file content, such as file signatures, against the expected type
- Limits of type checks, including files that are valid in more than one format
- Limits on file size, number of files, image dimensions, and storage per user
- Generating new file names instead of using names supplied by the client
- Risks of active content in documents, such as macros, scripts in SVG images, and formulas in CSV files
- Rewriting files into a safe form, such as re-encoding images, to remove unexpected content

## 12.3 Storing uploaded files

- Storage outside the web root, on a separate domain, or in object storage
- Preventing uploaded files from being executed as server-side code
- Authorization for access to stored files, linked to the owner or resource
- Malware scanning, quarantine until a scan completes, and the limits of signature-based scanning
- Access settings for cloud storage buckets, and the risks of public access
- Retention and deletion of uploaded files

## 12.4 Serving files to users

- Authorization checks before every file download
- Accurate `Content-Type` headers and `X-Content-Type-Options: nosniff`
- `Content-Disposition: attachment` for files that browsers should not render
- Serving user-supplied content from a separate site, a different registrable domain, to contain cross-site scripting, and why a subdomain or different port is not enough
- Encoding file names in response headers
- Time-limited, narrowly scoped signed URLs for direct downloads and uploads
- `Cache-Control` for files containing sensitive data

## 12.5 File paths from user input

- Path traversal through relative sequences such as `../`, absolute paths, and encoded variants
- Null bytes that truncate a path after an extension check in some runtimes and native file APIs
- Indirect references, such as identifiers mapped to stored files, instead of user-supplied paths
- Canonicalizing a path and checking, by path components rather than a string prefix, that it remains within the canonicalized base directory
- Why removing `../` from input is not a reliable defense
- Symbolic links that point outside an allowed directory
- Least-privilege file system permissions for the application as defense in depth

## 12.6 Archives and file processing

- Zip Slip: archive entries whose names write files outside the extraction directory
- Symbolic links inside archives
- Decompression bombs and limits on uncompressed size, number of entries, and nesting
- Vulnerabilities in file parsing and conversion libraries
- XML external entity processing in XML-based formats such as office documents and SVG images, as described in Module 4
- Processing untrusted files in an isolated environment with resource limits and timeouts

## 12.7 File inclusion and dynamic loading

- Local file inclusion and remote file inclusion when user input selects code or templates to load
- Allowlists that map user choices to fixed files
- Disabling remote file inclusion features in language runtimes

## 12.8 Fetching remote resources

- Server-side request forgery (SSRF) in features that fetch files or images from user-supplied URLs
- Restricting URL schemes to those required, such as `https`
- Allowlists of destinations and blocking internal and metadata addresses, as described in Module 13
- DNS rebinding, and connecting only to the address that passed the check
- Limits on response size, redirects, and time for remote fetches

## 12.9 Temporary files and race conditions

- Creating temporary files with library functions that use unpredictable names and exclusive creation
- Restrictive permissions on temporary files and directories
- Removing temporary files after use, including on failure paths
- Time-of-check to time-of-use (TOCTOU) race conditions between checking and using a file

## 12.10 Testing file handling

- Uploads with disallowed extensions, mismatched content types, and files valid in more than one format
- Uploads that exceed size, count, and dimension limits
- Archives containing traversal paths, symbolic links, and excessive compression ratios
- Path traversal and file inclusion payloads, including encoded variants
- Download requests for other users' files
- Internal addresses, metadata addresses, and `file:` URLs submitted to features that fetch remote resources
- Checks that uploaded files are not executed and are served with safe headers
