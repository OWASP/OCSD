# Objectives for Module 6 – Error Handling

This module covers how applications detect, handle, and report errors without disclosing information or weakening security controls.

A successful candidate can:

- Recognize how errors and unexpected conditions can disclose information, bypass security controls, or leave an application in an inconsistent state
- Identify internal details that error responses must not reveal, and distinguish user-facing messages from internal diagnostic information
- Recognize how differences in message text, status codes, and response times between error responses can reveal information
- Distinguish fail-secure from fail-open behavior, and identify the secure outcome when a security check or dependency fails
- Identify exception handling practices that preserve security, including handling at an appropriate layer, avoiding swallowed errors, and releasing resources
- Recognize the role of centralized error handling in producing consistent, safe error responses
- Distinguish development and production error configurations, and recognize the risk of detailed error output in production
- Identify the error information to record for diagnosis, and test cases that check error handling behavior

## Expected competency

Candidates can recognize whether an application handles errors securely.
They can identify error responses that disclose information, failure paths that grant access or leave inconsistent state, and missing or unsafe error handling.
